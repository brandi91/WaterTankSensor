2. ESP32 Board Model

The project uses an ultrasonic trigger/echo interface. Sensor RX, TX and sensor-power pins are not implemented.

6. Self-Test

Implemented initialization checks:

  • Settings Preferences open, load and pin validation with safe fallback.
  • LittleFS mount checks for the web server, history and persistent logging.
  • RGB LED startup color sequence when DEBUG_LED_TEST is compiled in.
  • Sensor GPIO initialization and measurement success/failure logging.
  • Battery ADC initialization and voltage validity checks.
  • Wi-Fi connection timeout and configuration validation.
  • MQTT buffer setup, connection and publish-result checks when MQTT is enabled.

Not currently tested: no comprehensive automated hardware self-test exists; wiring continuity, sensor accuracy, LED electrical operation and battery-divider values require physical verification.

7. Operating Modes

Automatic Mode: wake, synchronize time when available, measure, save history, publish MQTT when enabled, then deep sleep.

Web Mode: dashboard, settings, logs and this device information page.

Configuration AP: local recovery and network setup without saved Wi-Fi credentials.

Factory Reset: resets user settings and battery learning, and clears history and persistent logs.

8. Important Notes

  • Pin changes require a restart.
  • GPIO 33 remains fixed for recovery.
  • MQTT Discovery is manual only.
  • The battery ADC requires a voltage divider.
  • The web interface is normally disabled during deep sleep.
  • Factory reset removes saved configuration and history.
